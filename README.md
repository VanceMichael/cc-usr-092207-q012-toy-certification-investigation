# 玩具认证冒用排查

排查玩具认证编号冒用并追踪涉案批次的销售与召回。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括认证执法人员、玩具生产企业、经销门店、消费者通知人员。

资料所依据的领域事实如下：

- 案例中的玩具包装使用了属于其他产品的认证证书编号
- 涉案产品由生产企业供货至玩具店销售
- 监管部门根据仓库实物和销售数量作出处置

## 卷宗模型

`src/casefile.py` 在基础资料之上实现办案规则，`contracts/case.schema.json` 规定卷宗结构，`fixtures/case-012.json` 是对应的示例卷宗。规则落点如下：

- **证书有效产品范围**：证书只追加 `issued/suspended/restored/rebound` 事件；任一时刻的有效性、产品范围与版本号只回看当时已发生的事件，暂停、恢复或换绑不改变早先的市场事实。
- **按发生时间互相印证**：生产、入库、发货、收货、销售、抽样的先后由 `verify_timeline()` 校验（入库不得早于生产、供货不得早于入库、销售不得早于收货等）。
- **批量扫码与跨地区补报**：`merged_scans()` 以单件货物为键合并来源，同一件货只计一次（来源取并集）；同一货物的扫码结果互相矛盾时报错。
- **定性结论**：`assess()` 区分单一型号单一包装版本的 `packaging-rework`（包装返工失误）与多型号共用同一证书的 `systematic-misuse`（系统性冒用）；证据不足时为 `undetermined`，结论未澄清前 `sales_blocked()` 为真，不得继续销售。
- **门店范围**：`store_scope(门店)` 只返回该门店自己的批次、应下架数量（收货减已售）与应通知/已触达数量。
- **整改与材料**：企业可通过 `submit_rectification()` 补交整改，证据与整改材料只增不删，`remove_material()` 一律拒绝。
- **处置决定**：处罚或解除措施必须同时指向具体实物批次、批次生产时生效的证书版本、全部相关流向记录，以及每个供货门店的消费者触达结果（触达不得超过已售数量）；四者缺一不可，解除措施成立后才解除停售。

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方、事实和约束。卷宗测试覆盖上述全部规则，运行：

```
python -m unittest discover -s tests
```

仓库不保存账号、密钥、连接串或真实身份信息。
